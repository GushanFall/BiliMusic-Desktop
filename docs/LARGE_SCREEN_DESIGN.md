# BiliMusic 大屏版：首版功能与界面方案

状态：2026-11-15 已实现独立大屏客户端，正在进行本地验证；未发布。开发与构建见 [LARGE_SCREEN.md](LARGE_SCREEN.md)。

## 1. 产品定位

独立的 Android 大屏客户端，普通 Android 车机和 TV 共用一个 APK、一套页面和触控 / 遥控器交互规则。手机 APK 单独构建。沿用 BiliMusic 的音乐来源、播放核心、账号数据和坚果云 V2。

首版围绕四件事：打开能接着听、找到已有收藏、稳定播放、与其他端同步。复杂的资料整理留在手机和电脑，大屏读取整理结果。

本次不包含 Android Auto 投屏或 AAOS 的官方媒体模板集成。它们需要独立的媒体浏览服务与系统接入，不能通过横屏布局直接获得。普通车机侧载 APK 不承诺能读取车辆速度、接入仪表或识别厂商私有方向盘协议。

## 2. 功能迁移清单

| 功能 | 首版安排 | 大屏中的形式 |
| --- | --- | --- |
| 音频播放 | 完整保留 | 播放 / 暂停、上下首、进度、顺序 / 循环 / 随机、倍速、定时暂停；次级项放播放设置 |
| 后台播放与媒体控制 | 复用现有 Android 服务 | 通知、音频焦点、蓝牙 / 标准媒体键、后台切歌；不重写另一套播放器 |
| 上次播放 | 保留 | 恢复本机队列和进度，首页突出“继续播放”；冷启动默认不自动出声 |
| 合集与分 P | 核心保留 | 同 BV 分 P 与跨 BV 合集按原身份播放；选集、继续上次、章节标题统一使用共用规则 |
| 播放队列 | 精简保留 | 右侧抽屉，定位当前项；播放、下一首播放、移出、清空；首版不做拖动整理 |
| 我喜欢、歌单、关联收藏夹 | 保留浏览与轻量写入 | 读取原有分组与排序；可喜欢、加入现有歌单；关联条目保留链接图标与选择限制 |
| 收藏与关注 | 保留浏览 | 收藏文件夹、合集、已关注 UP 主、UP 主视频与合集；不搬备注 / 分组管理 / 导入关注 |
| 搜索 | 保留 | 歌曲、BV 号、UP 主；历史搜索、分页、列表内查找；系统输入法，不自建字母键盘 |
| 歌词 | 精简保留 | 自动匹配、搜索并选择版本、共用逐行 / 逐字时钟、读取其他端选择的版本；原文 / 音译 / 翻译切换，歌词页提供偏移微调 |
| B 站 AI 字幕 | 只读保留 | 在无合适歌词时按现有流程显示；不做字幕编辑器 |
| 离线播放与下载 | 精简保留 | 单曲 / 当前列表下载，独立音质与格式选择、进度、失败重试、移除离线副本；保留应用离线副本，安卓同时导出到 Download/BiliMusic 或系统授权文件夹 |
| 音质、起播缓存 | 保留 | 默认快速起播 / 预缓存下一首；自动最高不含 Hi-Res，手动高音质放次级菜单 |
| 登录 | 保留 | B 站二维码，过期自动提示刷新，遥控器可刷新 / 取消；不强制登录后才能体验允许匿名播放的内容 |
| 坚果云 V2 | 完整复用协议 | 首次配置、自动同步、立即同步、状态 / 重试 / 断开；沿用冲突自动合并规则；需要选择的差异有大屏处理入口 |
| 听歌统计 | 保留记录与汇总 | 照常纳入同账号总时长；首版不迁移复杂图表、热力图和完整排行榜页面 |
| 主题与显示 | 保留并精简 | 深色默认，支持浅色；界面大小、歌词字号、屏幕常亮仅限播放页的选项 |
| 在线歌单 / 歌曲文本导入 | 不迁移 | 在其他端导入后同步普通歌单 |
| 悬浮歌词 / 桌面歌词 | 不迁移 | 不展示入口，大屏产物移除悬浮窗权限 |
| 评论、回复、表情 | 不迁移 | 首版移除整套交互与入口 |
| 弹幕 | 保留 | 视频小窗与全屏复用共用渲染器，支持开关、字号、透明度和密度 |
| 音频 / 视频切换 | 首版保留 | 当前歌曲 / 分 P 内切换，继承队列、进度和暂停状态；支持全屏、选集与返回音频，不另建视频首页 |
| 歌曲信息、歌词手动编辑 | 不迁移 | 读取其他端已保存的修改与歌词选择 |
| 新建 / 重命名 / 删除歌单和文件夹、拖动排序、批量管理 | 首版不迁移 | 读取已有结构和排序；播放所需的喜欢、加入现有歌单不受影响 |
| 本地音乐、托盘、桌面快捷键、共享导出 | 不迁移 | 不属于大屏首版闭环 |

“加入歌单”依然复用既有能力判断：整部多 P 视频不加入普通单曲歌单，单独分 P 不加入 B 站整视频关联收藏夹；目标列表直接排除不可用选项。

下载的音频属于本设备。云同步传音乐资料和听歌记录，不把手机上已下载的音频传给车机。首版不改变这一规则。

## 3. 统一界面结构

```text
┌──────────────┬────────────────────────────────────────────────┐
│ BiliMusic    │ 页标题                          账号 / 同步状态 │
│              │                                                │
│ 此刻         │ 当前页面内容                                   │
│ 音乐库       │ 首页：继续播放 + 我喜欢 / 已下载 + 最近常听     │
│ 搜索         │ 音乐库：歌单 / 收藏 / 关注                     │
│ 离线         │ 列表：大行高、标题、歌手 / 来源、时长           │
│              │                                                │
│ 设置         │                                                │
├──────────────┴────────────────────────────────────────────────┤
│ 封面 / 歌名          上一首  播放/暂停  下一首        队列     │
└───────────────────────────────────────────────────────────────┘
```

保留五个导航项：“此刻、音乐库、搜索、离线、设置”。不再把“我的”“已收藏”“歌单”做成互相重叠的一级入口。

使用同一套页面，不按 TV / 车机自动切成不同产品。较窄横屏减少卡片列数、收紧非关键留白；超宽屏增加内容区宽度，不把控件拉散到屏幕两端。屏幕密度、系统字体及逻辑视口一起参与计算，不按物理分辨率简单放大。

### 此刻

- 第一屏突出上次歌曲 / 章节、进度和一个“继续播放”按钮。
- 右侧两个快捷入口：我喜欢、已下载。
- 下方显示最近使用的歌单 / 合集；不引入全站推荐流、轮播广告位和复杂统计。
- 首次没有资料时显示“搜索音乐”“登录 B 站”“连接坚果云”，不显示空白的继续播放卡。
- 恢复队列不等于自动开播，返回后台再回来不重置播放与焦点。

### 音乐库与列表

- 顶部三个分类与现有产品一致：歌单、收藏、关注。关联收藏夹在歌单中，使用小链接标记区分。
- 上层以封面卡片进入，下层采用纵向歌曲 / 章节列表；上下滚动为主，不做需要横向拖动的密集嵌套轮播。
- 列表标题区只放“播放全部、查找”，其他动作进入明确的“更多”入口。
- 每行默认是一个焦点，OK 播放；列表公共“更多”可对当前选中歌曲执行加入队列 / 歌单、下载等操作。触控同样可达，不依赖长按或遥控器额外菜单键。
- 当前播放项用音符 / 声波和主题色标识；焦点用独立描边，不能把“正在播放”和“光标停留”混为一谈。
- 长标题默认最多两行；聚焦后可查看完整标题。只有确需展示的聚焦 / 当前标题使用慢速滚动，不让所有行同时跑马灯。
- 从 UP 主进入合集再返回，恢复分类、分页、原条目焦点和滚动位置。不是返回后再定位到当前播放项。

### 正在播放

```text
┌──────────────┬────────────────────────┬────────────────────────┐
│ 导航         │ 返回浏览               │                队列    │
│              │                        │                        │
│              │        大封面          │ 上一句                 │
│              │                        │ 当前歌词 / 字幕        │
│              │ 歌名、歌手 / 章节来源  │ 下一句                 │
│              │ 进度与时长             │                        │
│              │ 上一首  播放  下一首   │                        │
│              │ 喜欢   模式   播放设置 │                        │
└──────────────┴────────────────────────┴────────────────────────┘
```

- 播放页内不重复显示底部播放栏。
- 封面与大按钮常驻，歌词在右侧；无歌词时仍展示歌曲信息和下一首，不出现空洞大框。
- 播放设置容纳倍速、音质、定时暂停、歌词偏移等，不把全部图标铺满主界面。
- 标题区在队列旁保留“视频 / 音频”切换。进入视频后在歌词旁以小窗展示，保留右侧歌词；点击小窗才进入全屏，不改变当前 BV / CID、队列、播放进度及用户暂停意图。
- 切换复用现有音画衔接流程，音频继续作为单一声音来源；画面准备就绪后再对齐显示，防止双重发声、回到 0 秒或重复记统计。切回音频、视频失败或应用退到后台时释放画面，保持原播放状态与音频焦点规则。
- 视频控制包括播放 / 暂停、进度、上下首、选集、清晰度、全屏。控制层空闲 3.5 秒后隐藏；隐藏时首次按键只唤出控制并恢复焦点，下一次执行操作。返回键在控制层隐藏时先唤出，显示时退出全屏；普通视频页再返回浏览，不连带停止音频。
- 另提供“简洁播放”显示方式，沿用同一布局，右侧改为大标题和下一首，弱化长文本。TV 也可使用；不是另一套车机专属产品。
- 普通侧载应用无法统一可靠获取行车状态。首版不宣称自动识别行驶 / 停车，不让“简洁播放”变成虚假的驾驶安全认证。

### 队列与弹层

- 队列用右侧面板，主界面保留背景上下文，面板中突出当前曲。
- 打开时焦点进入面板，背景不可聚焦；返回优先关闭面板，归还给原按钮。
- 选择歌曲后保留队列上下文，不强制跳走。移除当前项、清空等动作有明确取消路径。
- 不使用手机的滑动底部面板作为唯一交互，不依赖点击空白才能关闭。

### 搜索、登录与同步

- 搜索用整行输入框加“搜索”，输入聚焦时调用系统键盘。最近搜索可直接点选；不画一个实际上不能调用识别能力的麦克风按钮。
- B 站扫码登录突出二维码和到期状态，刷新、取消两个大按钮；不会复制手机登录弹窗后原尺寸显示。
- 坚果云首次配置保留一次性的邮箱 / 应用密码输入，使用系统输入法；已有凭据不进原型、不显示在大屏公开区域。凭据留本机，不随音乐库同步。
- 手机辅助输入 / 扫码配网作为后续能力，需要专门的配对和凭据传输设计，首版不附带临时公网中转服务。
- 同步状态轻量显示“已同步 / 同步中 / 待处理”。不逐首弹提示，不因一次连接失败覆盖整个音乐库。
- 必须保留同步差异处理：共用自动合并，余下重要差异可在大屏选择；不能只让用户去手机处理而本机永远卡住。

## 4. 遥控器与触控规则

| 输入 / 情形 | 行为 |
| --- | --- |
| 方向键 | 在可见按钮、网格、歌曲行间移动焦点；边界不意外切歌 |
| OK / Enter | 执行当前焦点动作，单次触控直接执行，不要求先点亮再点一次 |
| 原生播放 / 上下曲键 | 经 MediaSession 处理；前端不重复消费同一个按键 |
| 进度条 | 聚焦后按 OK 进入调整，左右步进，长按加速；OK 确认、返回取消；普通方向导航不直接改进度 |
| 返回 | 弹层 / 视频全屏 → 当前详情 → 上级列表 / 分类 → 此刻 → 系统桌面；不循环、不靠反复确认阻止离开 |
| 列表焦点 | 稳定条目 ID，分页和重渲染后不丢失；加载更多后焦点留原条目 |
| 弹层关闭 | 返回原触发控件；原项已移除则定位邻近可用项 |
| 触控 / 遥控器混用 | 点击不改变页面结构；下次方向输入从当前操作点继续 |
| 隐藏 / 禁用元素 | 不进焦点链；侧栏、内容、播放栏和弹层各有确定出入口 |

所有核心动作仅用 D-pad、OK、Back 可完成。触控不能是遥控器的补丁，遥控器也不能以右键、hover 或拖拽为前提。

## 5. 视觉方案

沿用现有 BiliMusic 配色和图标语言，深色默认、浅色可选；不移植其他音乐软件的品牌色和皮肤。

| 设计量 | 初始值 / 原则 |
| --- | --- |
| 深色底 / 面板 | `#09141B` / `#14252F` |
| 正文 / 次要文字 | `#EDF5F7` / `#9BB1BD` |
| 主题色 / 焦点描边 | `#77D4DF` / `#D4F8FC`，浅色换为更深青色 |
| 字体 | 系统中文无衬线字体，标题、正文、辅助信息建立三层；不捆绑大体积字体 |
| 主要交互目标 | 起始设计 56–64 dp，主播放按钮 72–80 dp，按逻辑密度与界面大小设置校准 |
| 文本起点 | 页标题约 30–36 sp，列表主标题 22–26 sp，辅助信息 16–20 sp；最终按观看距离调整 |
| 焦点 | 约 3 dp 高对比描边与轻底色，预留轮廓空间；不依靠大幅缩放引起布局跳动 |
| 留白 | 避开车机系统栏 / TV 裁边，内容区保留安全边距；不贴屏幕物理边缘 |
| 动画 | 焦点与展开约 120–180 ms；低配减少动画，歌词保持流畅；不使用持续全屏模糊和视觉特效 |

这些是初始设计 token，不把物理像素当 dp。首轮以 1024×600、1280×720、1920×1080 和超宽横屏建立测试矩阵，并测试系统字体、显示密度和可调 UI 大小。

## 6. 共用代码与独立包边界

- 主分支继续维护。增加静态构建目标和 `src/large-screen/` 页面壳，不新增长期车机 / TV 分支。
- 大屏保持 Android 原生播放平台身份，新增独立布局身份。`platform.ts`、`main.tsx` 中的平台和手机手势不能只靠“屏幕变宽”切换。
- 复用 playerStore、Android 音频桥、PlaybackService / NativeQueue、B 站提供商、SQLite、歌词时间轴、标题策略、同步与缓存；主要新工作是视图、焦点管理和精简流程。
- 视频复用 `SyncedVideo` / `videoSync`：静音画面跟随同一音频时钟，补遥控器唤出控件、焦点保护与全屏焦点归还。原生全屏逻辑适配已有横屏，不反复强制旋转。
- 独立 package ID（建议 `app.bilimusic.large`）、图标标识和应用名。手机与大屏可共存，但需要各自登录和配置同步，不能直接跨应用读取 Cookie / WebDAV 凭据。
- 同步继续完整兼容现有 V2。未迁移的编辑界面不等于删除其数据字段，不能把空白界面当作远端数据删除。
- 大屏前端按功能白名单组织入口，评论、导入、悬浮歌词等不随整套手机版入口被动打包。
- 原生插件声明的悬浮窗权限在大屏产物合并时移除。补 TV banner、Leanback 启动入口与非必需触屏声明。
- 当前手机生成清单也存在 Leanback 入口。拆包时在 `android-prepare` 等可复现脚本中给手机移除、给大屏保留，不能手改忽略目录后忘记还原。
- 构建隔离前端产物、生成工程与输出目录，防止先构建手机再构建大屏时混入入口、版本或资源。
- 基线先沿用 Android 8.0+，先验证 ARM64；32 位电视需再验证 ARMv7 依赖后提供同一大屏发行版的兼容包 / 通用包。车机与 TV 共包并不等于所有 CPU 自动兼容。
- 旧 WebView 单独探测与验证，为关键 CSS 提供回退，不把“Android 版本足够”当作 WebView 一定可用。

## 7. 实施顺序与验收

1. **播放闭环**：独立包与大屏入口、焦点导航、首页、二维码登录、已有资料库、搜索、合集 / 分 P、播放页、音频 / 视频切换与全屏、队列。
2. **补齐首版**：坚果云配置与冲突入口、离线下载与播放、精简设置、歌词 / 字幕、模式与进度、字体 / 显示大小。
3. **可靠性验收**：后台连续切歌、导航抢焦点后恢复、蓝牙 / 媒体键、弱网 / 重连、启动与进程重建、大列表焦点、同步和账号隔离。

第 3 步是首版交付门槛，不是发布后的可选工作。当前整个进程已被结束时，媒体键还不能无界面重建 Rust 播放解析链；首版承诺打开应用后恢复队列与进度，不承诺车机上电 / 杀进程后自动开播。

至少验证：

- 1024×600、1280×720、1080p TV、超宽横屏的明暗主题、长标题和大字号。
- 完全不用鼠标，从扫码登录到同步、浏览、搜索、选分 P、播放、返回，D-pad + OK + Back 全闭环。
- 从 UP 主合集返回恢复原焦点和位置，分页 / 网络更新不把焦点送回顶部。
- 前台、回桌面、WebView 挂起、音频焦点中断、蓝牙断开、失效音源恢复和连续切歌。
- 音频 / 视频反复切换、切换前暂停、视频加载失败、全屏返回、后台恢复；保持相同进度、分 P、单一路声音，不重复累计统计。高分辨率解码能力不足时可选较低清晰度。
- 新设备接入已有 V2，多端离线修改后合并；隐藏功能不丢数据，播放与下载不触发逐项云同步。
- 无网启动后仍可访问已下载歌曲；断网与失败重试不清掉已有列表。
- 手机包无 TV 入口，大屏包无悬浮窗权限；身份、ABI、图标、覆盖更新分别校验。

## 8. 参考与取舍

- [Android TV：Design for TV](https://developer.android.com/design/ui/tv/guides/foundations/design-for-tv)：远距离观看、大字与有限信息量；适用于 TV，不把其空间尺度机械套成手机。
- [Android TV：TV navigation](https://developer.android.com/training/tv/get-started/navigation)：D-pad 的明确焦点、可预测返回和完整可达路径。官方纯 TV 建议不额外显示软返回；本方案兼顾触控车机，因此保留统一的“返回浏览”入口，这是产品取舍。
- [Jellyfin Android TV 0.19 官方介绍](https://jellyfin.org/posts/androidtv-v0.19.0/)：参考其 TV 搜索与音乐队列 / 进度控制的完整性，不照搬视频优先的首页。此文章是已核对的 2025 年版本介绍，不表示当前最新版本。
- [Plexamp 官方介绍](https://www.plex.tv/plexamp/)：参考音乐库优先、车载使用、离线与预缓存的产品组织。它的 Android Auto / CarPlay 属于系统集成，不能据此宣称本项目已具备相同能力。
- [Google 车载媒体概览](https://developers.google.com/cars/design/automotive-os/apps/media/overview)：区分浏览、播放及系统模板。原站已提示后续更新迁移，本文只用来核对架构边界，不将其当作新平台认证依据。
